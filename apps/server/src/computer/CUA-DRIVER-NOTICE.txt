The adapter stages ONLY the MIT-licensed cua-driver executable. It does not
install Cua Spaces, cua-spacesd, Cua Driver Bench, optional perception/model
extensions, language SDKs, agent configuration, autostart entries, or a cloud
account. The pinned CLI links macOS system frameworks and does not require the
SDK dylib or Node addon shipped in the same archive.

The explicit setup operation downloads and verifies this archive, extracts the
CLI into the current server's stateDir/computer/cua-driver/0.38.0 directory, and
keeps the following license beside it. Normal operations never auto-install.
A distributor may pre-stage that same pinned executable and LICENSE.txt there.
A desktop packager embedding it should preserve host TCC attribution and sign
nested executable code as part of the host's normal signing pipeline. macOS
Accessibility and Screen Recording grants still belong to the responsible host
app. Driver setup reports these grants without requesting or modifying them.
